Setting up a broadcast

Everything you need to put Epinoia's graphics on a stream: the live scorebug, lower thirds, the team comparison, the final board and the squad screens, drawn from the same numbers as the box score and moving by themselves. Works with OBS, vMix, Wirecast, Streamlabs and anything else that can show a web page.

What you need

  • An Epinoia account with the right to broadcast the game. That is a league admin, a manager of either club (from the club portal), or a statistician assigned to the game. Sign in on the site first; the buttons only appear to accounts that may use them.
  • Streaming software that can show a web page. OBS Studio (free) is the one this guide walks through; the same URL works in vMix, Wirecast, Streamlabs Desktop, CasparCG and Singular.
  • The game's page on Epinoia. Every fixture has one — from the fixtures list, the league home or a club's profile. The broadcast button lives there.
  • For a FIBA LiveStats game: nothing extra. The league's feed is read for you. For a game scored in the Epinoia app, the statistician's phone or laptop does the scoring as usual.

Step 1 · Arm the game for broadcast

1

Open the game's page on Epinoia while signed in. Above the scoreboard you will see score this game → (for a game you may score) or broadcast this game → (for a federation-fed game, or if you manage a club in it). Press the caret beside it and choose Prime for broadcast. That opens the control room for this fixture in a new tab.

You can do this any time before tip-off — the graphics draw the real teams, crests and colours from the fixture alone, so you can lay everything out in the afternoon and leave it. Nothing needs a ball to have been thrown.

For a FIBA LiveStats game the control room also arms the live heartbeat: while it is open, the league's feed is read every couple of seconds and the graphics follow it. The arming lasts four hours and renews itself while the control room stays open, so keep that tab open for the game (it can sit behind OBS). See FIBA LiveStats games below.

Step 2 · The control room

2

The control room is the page you drive the graphics from. It shows the fixture, a preview of whatever is on air, and a tile for every scene. The important controls:

  • position and scale — where the scorebug sits on the picture (bottom left is the broadcast convention) and how big it is. The preview updates as you change them.
  • take on a tile — puts that scene on air on every layer that is listening. clear takes everything off.
  • the live layer URL — one address that shows whatever the control room has taken. This is the URL to give your streaming software, so you change scenes here and never touch OBS during the game.
  • per-scene URLs — every tile also has its own fixed address (a scorebug that is always the scorebug, a squad screen that is always the squad screen). Use these if you would rather switch scenes inside OBS with hotkeys.
  • OBS scene collection / vMix preset / Wirecast sheet — one-click exports that build the sources for you. The OBS one imports as a ready-made scene with every graphic already placed.

The tag at the top right says live layer connected once the control room can talk to the layers. If it says not connected, the fixed URLs still work — only the take/clear buttons need the connection.

Step 3 · Add the layer in OBS Studio

3

the quick way

  1. In the control room press OBS scene collection. A small JSON file downloads.
  2. In OBS: Scene Collection → Import…, pick the file, then switch to the imported collection (Scene Collection menu). A scene called Epinoia graphics appears with a browser source for the live layer and one for each fixed scene.
  3. Drag the browser source you want above your camera in the Sources list. The background is transparent, so only the graphic shows.

the manual way

  1. Sources → + → Browser. Name it "Epinoia live layer".
  2. URL: copy the live layer URL from the control room. It looks like https://prophesyscouting.co.uk/epinoia/broadcast/?g=…&live=1&pos=bl.
  3. Width 1920, Height 1080 (or your canvas size). FPS 30 is plenty.
  4. Leave Custom CSS as it is (OBS's default line makes the page background transparent, which is what you want).
  5. Untick "Shutdown source when not visible" — otherwise OBS unloads the page whenever it is hidden and it has to reconnect when you switch back.
  6. Tick "Refresh browser when scene becomes active" if you switch scenes a lot; it is harmless.
  7. OK. The scorebug appears in the corner you chose. Resize with the red handles if you must, but the scale control in the control room does the same thing without blurring.

OBS renders browser sources in its own copy of Chromium. If a graphic looks wrong there but right in your normal browser, right-click the source → Refresh. An update to the graphics only reaches OBS on a refresh.

vMix, Wirecast, Streamlabs and others

  • vMix — press vMix preset in the control room and open the file, or add an input of type Web Browser with the live layer URL at 1920×1080. Tick transparent background.
  • Wirecast — Wirecast sheet gives every URL; add a Web Page source per line.
  • Streamlabs Desktop — same as OBS: a Browser Source with the live layer URL, 1920×1080, shutdown-when-not-visible off.
  • CasparCG / Singular / vizrt HTML — point the HTML engine at the same URL. Every graphic is drawn at the render size you give it and scales with the scale parameter.
  • A hardware mixer that only takes a key + fill — use &chroma=00ff00 on the URL to paint the background a key colour instead of transparent, and key it in the mixer.

Every scene URL accepts pos (bl, bc, br, tl, tc, tr, c), scale (0.5 to 2), home / away (override a colour as rrggbb), safe=0 (drop the title-safe margin) and chroma. The live layer (live=1) ignores scene and shows whatever the control room has taken.

FIBA LiveStats games

Games that a federation scores in FIBA LiveStats are read into Epinoia by the ingest worker. Normally that happens every ten seconds — fine for a box score, visibly late on a scorebug. So a game can be armed:

  • Opening the control room (or the caret's Prime for broadcast) as a club or league admin arms the game for four hours and re-arms it every half hour while the control room stays open.
  • While armed, the worker reads the game's feed every two seconds and the graphics layer polls the store at the same rate. Expect the scorebug to trail the arena's own scoreboard by two to five seconds — the feed itself is a few seconds behind the table, and that part is the federation's.
  • The clock on the scorebug runs on its own and is corrected by each reading; for a clock that matches the hall exactly, keep it yourself or point a camera at the board — see the clock.
  • Nothing else changes: the same scenes, the same control room, the same URLs. The statistician is at the federation's table; you only stream.

Keep the control room tab open for the whole game. If it is closed, the arming runs out after four hours and the graphics fall back to the ten-second read. You can re-open it at any time to re-arm.

arming without our graphics

Arming is worth doing even when the stream carries someone else's graphics, or none. Every play the feed reports is stamped with the moment it was read, and under the heartbeat that stamp is tight to two seconds. When the game's YouTube stream is attached afterwards, those stamps place every play in the video on their own, and the AI worker that reads the scoreboard off the footage uses them to know where to look and to check what it read. So: open the control room at tip-off, leave it open, and the video work after the game is a great deal easier.

The clock

A scorebug lives or dies by its clock, and the clock is the one thing a federation feed cannot give you well: FIBA LiveStats publishes the time as a snapshot that moves when the table syncs an action, and Genius's own page does not tick it between reads. So the graphics run their own clock and use whatever source you give them to correct it, sliding towards each correction rather than jumping. You have three sources, in rising order of quality.

using the clock keeper

  1. Open the control room. The clock keeper panel sits above the preview, seeded from the feed (or 10:00 before tip).
  2. Press start as the ball goes up, stop on every whistle, start on the inbound. Space is the same key so you can keep your eyes on the floor.
  3. −1 s / +1 s nudge it; set takes a time like 7:42; P−/P+ move the period (P+ puts the clock back to full).
  4. Leave follow the feed ticked: a fresh reading from the table that disagrees by more than 1.5 s re-bases you silently. Untick it if the table is the thing that is wrong.
  5. release hands the clock back to the feed (or to the camera).

using the clock cam on a phone

  1. In the control room, the Phone clock cam card shows a code. Scan it with the phone (or send yourself the link beside it): the app opens already on this game. The card turns to "phone connected" as soon as the app is open, and shows the phone's last reading once it is sending. You can also open Clock cam (phone) from the game's broadcast caret, or find it under Take part on the league home.
  2. Install it: on Android and Chrome the app shows an install button in its header; on iPhone use Share → Add to Home Screen. It then opens like any other app, full screen, and remembers your boxes.
  3. Allow the camera, prop the phone where the whole scoreboard is in shot and still — a clamp on the table rail is ideal — and press box the clock, then drag a rectangle tightly round the clock digits, colon included. Box the two scores the same way if you want them sent too.
  4. The thumbnail under the controls shows what the phone sees after it has picked the digits out. If it reads wrong, nudge threshold or tick light digits on dark. The boxes are remembered for this game on this phone.
  5. Press connect & send. Once the clock has been seen running (or repeated), every reading goes to the graphics; the control room's clock tag changes to "the camera is keeping it". P−/P+ set the period.
  6. If the board defeats the phone's reader — a dim or dot-matrix board — tick read on the league's PC instead: the phone posts the boxed crop a few times a second and the PC's scoreboard model reads it (below, with --source phone).

using the clock cam on the league's PC

  1. Point a camera at the arena's scoreboard so the digits are level, sharp and at least 20 pixels tall. A phone on a clamp at the table streaming over RTSP (IP Webcam on Android, or any IP camera) is enough; a webcam on the PC works; so does a YouTube stream that keeps the board in shot.
  2. On the league's PC (the one the video worker runs on) start the reader with the game's id: 
    python scripts\worker\clock_cam.py --game <game-id> --source rtsp://192.168.1.20:8080/h264_ulaw.sdp
python scripts\worker\clock_cam.py --game <game-id> --source 0            # the PC's own webcam
python scripts\worker\clock_cam.py --game <game-id> --source https://youtu.be/…   # a stream showing the board
python scripts\\worker\\clock_cam.py --game <game-id> --source phone            # the crops a phone app is posting
    Add --show to see what it is reading with the clock boxed in green.
  3. It prints "locked on the clock" once it has found the digits and seen them run, then pushes every reading. The control room's clock tag changes to "the camera is keeping it"; the keeper's keys still work on top if you ever need to step in.
  4. Delay is about a second: the read cadence plus the push. Leave it running until the final board.

Precedence: a keeper's tap or a camera reading holds the clock for twenty seconds; while one of those is fresh the feed can change the score and the fouls but not the time. When both go quiet the layers fall back to the feed on their own.

Games scored in the Epinoia app

If the statistician scores the game in Epinoia's own scoring app, nothing needs arming. Every tap is pushed to the graphics the moment it is recorded and the clock ticks on the layer itself, so the scorebug is as live as the table. The scoring app is the third item under the caret on the game page.

Data for Vizrt, Chyron, XPression, vMix data sources

Systems that fill their own templates can poll the same state as a JSON document instead of showing the page:

GET https://hhvofgqqadtyvcjudhjx.supabase.co/functions/v1/broadcast?g=<game-id>

The document carries the two teams, the score, period and clock, fouls, timeouts, the last play, both box scores and the players of the game, under stable field names that do not change during a season. Poll it every one to three seconds. The same document is what the page draws from, so a template and the layer can never disagree.

Match-day checklist

  • Signed in on Epinoia as a league admin, a club manager or the assigned statistician.
  • Game page open; Prime for broadcast pressed; the control room open in its own tab and left open.
  • For a LiveStats game: the control room's heartbeat tag reads armed.
  • The live layer added in OBS at the canvas size, "shutdown when not visible" off, above the camera.
  • Position and scale checked on the preview against the real floor and the real lighting.
  • Crests and colours read correctly; overrides added if a kit clashes with the floor.
  • A test take: scorebug on, lower third on, clear — all seen in OBS.
  • At the end: take the final board, then clear.
