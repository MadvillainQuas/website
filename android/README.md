# Epinoia for Android

The Epinoia app is a **Trusted Web Activity (TWA)**. It opens the live website,
`https://prophesyscouting.co.uk/epinoia/home/?source=twa`, full screen in Chrome with no URL bar.
The app adds the native parts a website can't have:

- its own icon, and a splash screen in HOME's colour (`#f3faf6`)
- a **Game alerts** notification channel (`epinoia_alerts`, importance HIGH)
- a native notification permission request on first launch
- a native notification settings screen

Website changes never need a new app. The app shows whatever the site serves on its next launch.
A new APK is only needed when something in this folder changes.

## What's in here

```
android/
  settings.gradle, build.gradle, gradle.properties
  app/build.gradle                     version from version.json, env-var signing
  app/src/main/AndroidManifest.xml     TWA metadata, delegation service, App Links, settings deep link
  app/src/main/java/uk/co/prophesyscouting/epinoia/
    EpinoiaLauncherActivity.java       forces Chrome, first-launch pre-prompt, shell/notif/chan on the URL
    EpinoiaDelegationService.java      re-posts Chrome's notifications on Game alerts
    Channels.java                      creates epinoia_alerts and reports its importance
    NotificationSettingsActivity.java  the native settings screen (epinoia://notification-settings)
  app/src/main/res/                    icons and splash (PNG per density), colours, strings, themes
  (icons are built from brand-source/mark.png at the repository root)
  store/icon-512.png                   Play Console's store icon
```

The project was written by hand from android-browser-helper's `demos/twa-basic` and Bubblewrap's
template. It is not generated by Bubblewrap, and CI never runs Bubblewrap: its first run installs a
JDK and the Android SDK, and offers to create a signing key in the target folder, which here would
be the public repo. There is no Gradle wrapper, because `gradle-wrapper.jar` is a binary and a `gradlew` committed from
Windows loses its executable bit.

## The icon

Every icon PNG is generated from `brand-source/mark.png` by `tools/build-brand-icons.py`: the
launcher icon (adaptive, themed on Android 13+), the legacy icons for Android 6 and 7, the splash
mark, the store icon and the download page's icon. To change the logo, replace that file, run the
script from the repository root (`python tools/build-brand-icons.py`, needs numpy, Pillow and
scipy), raise `versionCode` in `epinoia/android/version.json`, and push. A new icon only reaches
phones in a new APK. The notification icon, `drawable/ic_stat_epinoia.xml`, stays the Λ
silhouette: a wordmark cannot be read at 24 dp.

## Why the launcher forces Chrome

android-browser-helper normally opens the TWA in the phone's **default** browser if that browser
supports TWAs. On a Samsung phone that browser is Samsung Internet. The library's own
[browser support table](https://github.com/GoogleChrome/android-browser-helper/blob/main/docs/trusted-web-activity-browser-support.md)
lists Samsung Internet with **no splash screen and no notification delegation**. So a stock TWA on
a Samsung would repeat the exact bug the app exists to fix: notifications posted by the browser at
its own settings, which never pop up.

`EpinoiaLauncherActivity.createTwaLauncher()` therefore passes `com.android.chrome` as the
provider whenever Chrome is installed and enabled. When it isn't, the app shows a dialog once
explaining that Epinoia needs Chrome, with a button to Chrome's Play listing (where a disabled
Chrome shows **Enable**). After that the library's default launch runs.

## How notifications work

1. The site's Web Push goes to Chrome as before: `notify`, tags, topics and receipts are unchanged.
2. Chrome hands the notification to `EpinoiaDelegationService` instead of posting it itself.
   Declaring that service in the manifest is what turns delegation on.
3. The service rebuilds the notification with `Notification.Builder.recoverBuilder` onto
   `epinoia_alerts` (IMPORTANCE_HIGH, vibration, public on the lock screen) with the white Λ
   silhouette as its small icon. The icon is built with `Icon.createWithResource(getPackageName(), …)`:
   the recovered builder carries Chrome's context, so `setSmallIcon(int)` would point the icon at
   Chrome's resources. The stock library path would put the notification on an IMPORTANCE_DEFAULT
   channel, which never pops up.
4. Chrome's "may I notify?" question has two routes, and both are covered. The older
   `areNotificationsEnabled` call is answered from the app's notification switch, the Android 13+
   permission and Game alerts. The `checkNotificationPermission` extra command stays with the
   library, except that app notifications on with Game alerts off answers BLOCK (the library would
   say ALLOW, because Chrome's own channel never exists here).

On the first launch on Android 13+, the launcher holds the launch. It shows a one-screen pre-prompt
explaining Game alerts, asks for `POST_NOTIFICATIONS` natively, and then opens the site. The app
asks natively because the JavaScript permission answer is unreliable on One UI 8
(android-browser-helper issue #563).

Every launch URL gets three extra parameters, which `epinoia/appmode.js` stores:

| parameter | value |
|---|---|
| `shell` | this build's `versionCode`. The site asks for an update below `minShell`. |
| `notif` | `1` if Android lets the app post notifications, `0` if not |
| `chan` | Game alerts' importance: `4` is HIGH, `3` DEFAULT, `0` off, `-1` missing |

The site opens the native settings screen with
`intent://notification-settings#Intent;scheme=epinoia;package=uk.co.prophesyscouting.epinoia;end`.

**Pinned on purpose.** The delegation override depends on androidx.browser's notification path.
On every android-browser-helper bump, re-run the Phase 7 notification checks 1–4 on a real phone.

## How CI builds it

`.github/workflows/android.yml` (outside this folder) does the build. It needs:

- **JDK:** Temurin 17
- **SDK:** the Android SDK (platform 36, build-tools 36.0.0 for `apksigner`)
- **Gradle:** 8.14.5, installed by `gradle/actions/setup-gradle` with a pinned `gradle-version` and `cache-provider: basic` (the MIT cache; the default one is proprietary). AGP 8.13 needs Gradle 8.13 or later. The AGP pin here and `GRADLE_VERSION` in the workflow move together.
- **Before the key exists:** the workflow still runs `assembleRelease bundleRelease`, unsigned, so `lintVitalRelease` and the bundle are proven early.
- **Command:** `gradle --no-daemon assembleRelease bundleRelease`, run in `android/`
- **Signing variables:** the workflow decodes the `ANDROID_KEYSTORE_B64` secret to a temporary file and exports these for Gradle:

| environment variable | from |
|---|---|
| `EPINOIA_KEYSTORE` | absolute path of the decoded keystore file |
| `EPINOIA_STORE_PASSWORD` | secret `ANDROID_KEYSTORE_PASSWORD` |
| `EPINOIA_KEY_ALIAS` | secret `ANDROID_KEY_ALIAS` |
| `EPINOIA_KEY_PASSWORD` | secret `ANDROID_KEY_PASSWORD` |

Release signing is applied **only when all four are set**. Without them the release build is left
unsigned, so pull requests and a fresh checkout still build.

Outputs:
- `app/build/outputs/apk/release/app-release.apk` (`app-release-unsigned.apk` when unsigned), published as `epinoia.apk`
- `app/build/outputs/bundle/release/app-release.aab`, published as `epinoia.aab`

The release is tagged `android-v<versionCode>`.

To ship a new app version, raise `versionCode` (and `versionName`) in
`epinoia/android/version.json`. A new APK installs over the old one only if it is signed with the
same key and has a higher `versionCode`.

## Opening it in Android Studio

1. Install Android Studio, then open **File → Open** and choose this `android` folder, not the
   repo root.
2. Studio needs a Gradle version, because there is no wrapper. When it asks, or under
   **Settings → Build, Execution, Deployment → Build Tools → Gradle**, choose a local Gradle 8.14.x.
   Alternatively, create a wrapper locally and **never commit it**:

   ```bat
   cd /d C:\Users\Admin\Documents\website_repo\android
   gradle wrapper --gradle-version 8.14.5
   ```

   `android/.gitignore` ignores the wrapper files (`gradlew`, `gradlew.bat`, `gradle/wrapper/`),
   so they stay out of commits.
3. Set **Gradle JDK** to 17 or newer. Studio's bundled JDK works.
4. Run the `app` configuration on a phone with Chrome. Debug builds use Studio's debug key, so the
   site's `assetlinks.json` won't verify them and Chrome shows a URL bar. Only the release key
   gives the full-screen app.

To see the channel on a connected phone:

```bat
cd /d %USERPROFILE%
adb shell dumpsys notification | findstr /i "epinoia_alerts"
```

`mImportance=4` means Game alerts is HIGH.
